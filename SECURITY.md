# Security model and comparison

## Baseline

The baseline on this machine is Arch's `pinentry` 1.3.3-1, whose default wrapper selects `pinentry-gnome3`. That frontend delegates input to GCR and uses pinentry's secure-memory subsystem for its returned password. The relevant implementations are [pinentry-gnome3](https://github.com/gpg/pinentry/blob/pinentry-1.3.3/gnome3/pinentry-gnome3.c), [pinentry core](https://github.com/gpg/pinentry/blob/pinentry-1.3.3/pinentry/pinentry.c), and [GCR 3.41.2's secure allocator](https://github.com/GNOME/gcr/blob/3.41.2/egg/egg-secure-memory.c). These were read as references; their code is not vendored here.

The goal is comparable concrete protections for rbw password entry on this Wayland/Hyprland desktop, not a claim of identical assurance or complete GnuPG compatibility. Upstream pinentry and GCR have much more deployment history and independent scrutiny. Passing local tests is not a security audit.

## Password path

1. The compositor delivers a key event to a native Qt item with keyboard focus. A thin C++ binding passes the event's UTF-8 bytes directly to Rust and erases its transient conversion buffer. The accumulated password is never a QString, QML property, JavaScript string, JSON value, clipboard value, or undo-history entry.
2. Rust stores both password fields in dedicated anonymous mappings. `mlock`, `MADV_DONTDUMP`, and `MADV_WIPEONFORK` are required. Failure refuses the prompt; there is no ordinary-heap fallback. Each mapping has a 4096-byte capacity, is edited in place, and is zeroized before unmapping. Input is further limited to 996 bytes after Assuan escaping, so every password fits one data line. Rejected input latches an error in that field and prevents submission, including repeat verification, until Ctrl+U clears it for re-entry. Cursor movement and deletion cannot silently make a truncated prefix acceptable. Repeat comparisons use `subtle` over fixed-size buffers and lengths.
3. Native Rust sends a bounded binary frame over a private Unix socket directly to the Rust backend. Both ends authenticate the peer's kernel-reported UID and exact PID. The backend reads the payload directly into locked memory, without JSON parsing or an intermediate heap receive buffer.
4. The backend escapes directly from locked memory to the caller's stdout file descriptor, without Rust's ordinary stdout line buffer. Assuan data lines stay within 1000 bytes including framing; UTF-8 characters and percent escapes stay intact. Nonblocking pipe/socket writes check cancellation and share a two-second deadline for each complete protocol response, so a stalled or slowly draining caller cannot retain a secret indefinitely. It then zeroizes and releases its mapping. Cancellation and failure before delivery return no password data. A transport failure during delivery may leave the caller with an incomplete response; the connection ends without a successful completion.

Qt/Wayland still create transient key-event strings. Kernel socket/pipe buffers and the calling application's handling are outside this frontend's memory-erasure guarantee. This is also a boundary for ordinary graphical password entry; no claim of eliminating every copy is made.

### rbw data-line compatibility

[rbw 1.15's password reader](https://docs.rs/crate/rbw/1.15.0/source/src/pinentry.rs) returns after the first `D` line. A test with an isolated encrypted dummy vault confirmed it ignores a suffix in a second line. Although Assuan supports multiple data lines, this frontend therefore rejects passwords whose escaped form exceeds a single line's 996-byte payload. Both the native input session and backend enforce the limit before any password data is returned. `%`, CR, and LF each use three encoded bytes. The general data encoder still respects Assuan's line bound, but GETPIN never relies on a caller joining multiple lines.

## Process and UI protections

- Both backend and UI require `PR_SET_DUMPABLE=0`, `RLIMIT_CORE=0`, and `PR_SET_NO_NEW_PRIVS=1`. The UI uses the explicitly selected native startup guard through `LD_PRELOAD` to apply them before Quickshell main and QML initialization. The native input module requires the guard's initialization marker and reapplies hardening before accepting input; a missing or failed guard refuses the prompt. Same-user `/proc/PID/mem` access is tested from the ancestor test process after UI initialization. Root and processes with sufficient capabilities remain trusted.
- Linux resets dumpability during ordinary `execve`. The dynamic linker and shared-library initialization before the guard constructor remain a startup exposure interval. Hardening later does not undo an attacker attaching or opening process memory during that interval. Deployment therefore still relies on OS ptrace restrictions against untrusted processes, such as Yama's restricted policy, and trusts the launching caller. The guard narrows this interval but does not eliminate it. The backend also has its initial loader/runtime interval before Rust main. No system ptrace settings are changed by this project.
- The child gets an explicit environment allowlist, an absolute Quickshell path, forced Wayland, disabled input-method/accessibility bridges, and no inherited preload/QML/plugin/debug path overrides. Its only preload is the selected startup guard, checked alongside the package's other code paths. The backend's own initial loader environment is still part of the caller's trust boundary.
- The overlay requests exclusive keyboard focus. The native field refuses key events unless its window is active. Losing window activation after focus was obtained cancels and erases the input. This is not a compositor-independent secure-attention mechanism.
- There is no copy, paste, reveal, external password cache, or input undo feature. Ctrl+U clears the field. Arrow keys, Home/End, Backspace/Delete, Enter, Escape, and repeat entry are supported.
- UI startup has a separate ten-second limit; socket writes, acknowledgment reads, and protocol output have short transport limits. User interaction honors pinentry's timeout, including rbw's `--timeout 0` (unlimited). The output deadline applies to protocol pipes/sockets; ordinary files and devices are outside that transport guarantee. A disconnected stdout reader dismisses the prompt. EOF on command stdin does not cancel it, because rbw intentionally closes stdin after GETPIN.
- Normal errors and signals reap the particular UI child. Linux's parent-death signal kills it if the backend dies abruptly. No password is written to disk, logging, environment variables, or process arguments. A SIGKILL may leave an empty socket directory, but not a password file.
- Assuan input lines and native response frames are bounded. UI metadata uses a length-prefixed frame with a shared 65536-byte JSON payload limit. SET commands validate the aggregate escaped JSON size, including dialog framing fields, and reject oversized updates while preserving the prior accepted state. The backend validates again before launching the UI, and the UI rejects oversized or truncated frames. Unsupported protocol commands/options fail rather than claiming success. This frontend deliberately does not implement quality inquiries, password generation, external caches, or every GnuPG option.

## Code ownership matters

The development checkout is user-writable and is **not** equivalent to a root-owned system package against a malicious same-user process that can replace code before launch. For the installed configuration, use the supplied Arch package. It installs `/usr/bin/pinentry-omarchy` and its QML/native module under `/usr/lib/pinentry-omarchy`, owned by root. The installed backend rejects writable/non-root-owned UI code paths and never loads a temporary writable copy of the QML.

Theme files remain user-writable data, parsed for simple colors and numbers; they are not imported as QML or evaluated as JavaScript. Quickshell, Qt, system libraries, the compositor, kernel, root, the rbw caller, and package installation remain trusted. A compromised compositor can capture input or screenshots regardless of the frontend.

## Verification

`cargo test` covers locked-buffer editing/erasure, actual kernel mapping flags, peer PID rejection, overflow/re-entry and rejected repeat suffixes, bounded Assuan encoding, metadata frame limits and truncation, cancellation, malformed input, and signal/deadline cleanup with blocked stdout. A small C helper verifies that exec resets dumpability and that the startup guard restores protections before the helper's constructors/main. This test requires `cc`. It does not prove absence of the earlier loader exposure interval.

After `bin/build`, `bin/test-native` compiles the actual Qt field implementation into an offscreen test executable. It checks multibyte overflow, blocked submission, rejected repeat suffixes, Ctrl+U recovery, and the response sent through the native socket. Focus and key events are delivered inside that test process; it never injects keys into the desktop. It requires pkg-config and Qt GUI QPA headers.

`cargo test --test live -- --ignored --test-threads=1` additionally checks the actual desktop UI, repeat mismatch, zero-timeout/closed-stdin rbw behavior, process memory protections, environment isolation, and caller-disconnect cleanup. These opt-in tests inject dummy keys into the desktop and require an otherwise idle session. Run `bin/build` first so the native plugin and startup guard match the Rust library.

`python3 tests/rbw.py` exercises the real installed rbw/rbw-agent binaries with an encrypted dummy local vault, a unique profile, and temporary configuration/cache/data directories. Short dummy passwords pass through the real desktop frontend; cancellation, wrong-password retry, unlock state, list/get, locking, and automatic unlock are checked. The fixture points server endpoints at loopback and disables background sync. It uses no real account credentials and does not verify server login, registration, sync, or 2FA.

An independent review is still needed before claiming security assurance on par with the mature upstream helper. The implementation now targets comparable mechanisms rather than relying on masked QML strings and a disclaimer.
